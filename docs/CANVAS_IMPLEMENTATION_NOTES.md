# Canvas implementation

The app opens a plain canvas with bundled sample images. On the first nonzero viewport layout, all items are fitted into a grid spanning the screen, ordered from the top left across each row. The column count maximizes visible image area while preserving image proportions; a single image is as large as the viewport allows without cropping. Dense layouts can use images down to one world point rather than the previous 24-point minimum. The initial layout runs once per session so later viewport changes do not overwrite manual placement or camera changes. The supported interactions are:

- Hold an image for 0.35 seconds to pick it up: a medium haptic, 60% enlargement, 28-point upward lift and soft shadow confirm pickup and keep it visible around your finger. The preview returns to the image's original size on release; Reduce Motion keeps the enlarged preview without animating the transition. Continue moving the same finger to drag; release to place it. A normal swipe anywhere pans the canvas. Cancellation restores the placement, and adding a second finger hands control to pinch/zoom.
- While holding an image or group, bringing your finger within 64 screen points of any viewport edge scrolls the canvas toward that edge, including diagonally at corners. Scrolling accelerates toward the edge up to 480 screen points per second per axis and continues with a stationary finger. It stops when the finger returns to the interior, releases, adds a second finger, or the interaction is cancelled. Camera movement reapplies the active drag at the current zoom without triggering velocity-based detachment.
- Pinch directly on an image to resize it. Both fingers start inside its bounds, with at least one on opaque pixels. No prior selection is needed.
- Pinch elsewhere to zoom the canvas around the fingers, or use two fingers to pan.
- Camera swipes coast with their release velocity and exponential friction. A new touch stops the glide immediately; cancellation, backgrounding, viewport changes and removal from the window also stop it. Image and group placement stay precise without momentum.
- Nearby images receive a dashed group outline. New proximity connections form within 64 world points; existing groups stay connected up to 128 world points. During image dragging, existing group members resist outward movement with a progressively stronger rubber band, using a temporary elastic connection that can stretch beyond the normal 128-point boundary. Stretch is capped at 240 screen points and initially follows 95% of outward finger travel before resistance increases. Slow release returns the item to its pickup separation with a damped spring animation (instant with Reduce Motion). Outward finger-driven edge separation at 450 screen points per second breaks the connection; speed is measured before resistance so a stretched item can still be pulled free. Inward and sideways movement do not trigger velocity detachment. Broken connections remain excluded during the removal gesture. A fresh image drag clears exclusions involving that image, allowing either former member to re-form the group without first moving beyond the 128-point range; cancellation restores the exclusions. Connections also clear when the items leave the 128-point range. Lifted images still preview nearby groups, and cancellation restores membership as well as placement. Zooming does not change group membership. Each image remains independently movable and resizable. Hold the dashed border for 0.35 seconds to lift and drag the whole group with the same haptic and a shared shadow. Membership is fixed for the duration of the drag; proximity groups update normally after placement.

- Single-tap an image to open its resizable details drawer directly. Dragging, panning, pinching, and rotating never open the drawer. Details include the sample name, placeholder price and URL, colour, brand, and a status menu (Owned, Wishlist, Ordered, Returning, Returned, Sold). Status choices are kept per image for the current session. Delete image is the last row in the scrolling details list and asks for confirmation before removing only that placement and closing the drawer.

- Groups display a compact title above their images, chosen from `CanvasNamedGroup.placeholderNames`. Tap a title to edit its name and choose any background colour with the native iOS colour picker (or remove the background), with changes applied immediately. Swipe down to close the drawer; hold the title to move the group. Titles use 17-point semibold Dynamic Type and track presentation bounds throughout pickup, dragging and release. They stay hidden through 50% zoom, then fade in to full visibility at 75% zoom, so titles are visible at the default 100% zoom. Titles use a 44-point touch target and support VoiceOver activation. Names and background colours follow the largest surviving membership overlap after splitting or merging, and cancellation restores the original names. Names, like the canvas itself, remain in memory for this session.

Removed: sample catalog, persistent group membership, group resizing and explicit detachment, resize handles, undo/redo, export/share, workload controls and diagnostic counters. The fixture generator now generates only the six bundled sample assets.

Kept: anchored coordinate transforms, size/zoom limits, gesture cancellation and finger-transition handling, transparent-image hit testing, spatial queries, visible-layer culling, asynchronous image decoding/cache, and accessibility movement/resize actions.

Canvas state is held only in memory. Every new app session starts with the bundled sample layout and default camera; groups are derived from image positions and in-memory connection history. Layout saving, loading, legacy migration and saved-file recovery have been removed. Existing canvas.json files are no longer read or written.

## Validation

- Generic iOS build passed with signing disabled.
- A temporary check outside the project passed for group dragging at zoom, fixed membership, cancellation and pinch handoff. No test files or test target were added.
- Before removal, the core regression suite passed 10 tests with 0 failures. Test sources, the test target and its scheme were subsequently removed at the user’s request.

Physical-device multi-touch behavior, VoiceOver, frame rate and memory pressure still need hands-on validation. The spatial index and image cache remain in place; this change does not claim new performance measurements.
